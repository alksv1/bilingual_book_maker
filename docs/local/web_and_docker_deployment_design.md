# Bilingual Book Maker - Web & HTTP 接口与轻量部署设计方案

> 已落地的跨模块执行契约、回归测试与已知限制见 [Web 集成验证记录](web_integration_verification.md)。

## 1. 概述与设计理念

### 1.1 核心诉求
当前 `bilingual_book_maker` 采用 CLI 模式运行，对于单次调试或开发者十分方便，但在服务器长期驻留、无人值守批量翻译或多终端（如手机/平板/办公机通过浏览器）使用时存在以下痛点：
1. **进程脆弱**：依赖 SSH 终端或本地常驻终端，网络波动或机器休眠易导致任务中断。
2. **配置割裂**：配置（API Key、Base URL、Provider 参数）分散于命令行参数、环境变量或 `bbm_providers.json`，修改繁琐，不适合远程或非技术化操作。
3. **批量与进度可视化不足**：多本书籍连续处理缺乏队列管理，无法直观追踪每本书的翻译阶段（分块、翻译中、打包完成）。

### 1.2 零侵入设计原则（Non-Invasive Architecture）
- **核心逻辑零污染**：`book_maker/` 现有的 CLI 模块、解析器（loader）、翻译引擎（translator）、流水线（pipeline）代码保持完全独立，不耦合 Web 逻辑。
- **适配层外置**：新建轻量服务层（如独立目录 `web/` 或 `server/`），只作为顶层编排器调用既有核心函数或子进程执行。
- **配置双向解构**：网页端可视化配置直接映射并输出与既有格式完全兼容的 `bbm_providers.json` 及系统参数，底层机制维持 100% 一致。

## 2. 整体架构设计

```
+-------------------------------------------------------------+
|                      轻量前端界面 (Web UI)                     |
|  - 状态监控看板 (进度条/日志流)    - 批量书籍上传与管理 (拖拽)   |

+-------------------------------------------------------------+
                               |  HTTP / SSE / WebSocket
+-------------------------------------------------------------+
|                   HTTP API 服务层 (FastAPI)                  |
|  - 鉴权网关: 双模式 (开放式 vs Bearer/Session 认证)          |
|  - 配置管理器: 读写持久化配置，脱敏返回与动态注入             |
|  - 异步任务调度器 (Worker Queue): 支持多任务排队、取消与重试   |
+-------------------------------------------------------------+
                               |  调用既有 Python 接口 / CLI 执行层
+-------------------------------------------------------------+
|             BBM 核心翻译引擎 (book_maker/* - 保持原状)         |
|  - Loader (EPUB/PDF/TXT/SRT)     - Pipeline (分块/组合/导出) |
|  - Translator 适配器             - 费用核算与缓存机制          |
+-------------------------------------------------------------+
```

## 3. 双模式鉴权设计（公网部署 vs 局域网自用）

### 3.1 模式划分与行为
| 特性 | 开放模式 (Open Mode) | 保护模式 (Protected Mode) |
| :--- | :--- | :--- |
| **适用场景** | 局域网自用、Tailscale/WireGuard 异地组网、本地回环 | 公网直接暴露、VPS 开放端口、反代穿透 |
| **配置触发** | 环境变量 `AUTH_PASSWORD` 未设置或为空 | 设置了环境变量 `AUTH_PASSWORD=<your_secret>` |
| **网页访问** | 直接进入主控制台 | 首次进入弹出登录弹窗/页面，验证成功后写 HttpOnly Cookie |
| **API 接口** | 所有接口（上传、查询、修改配置）免认证直接放行 | 必须携带请求头 `Authorization: Bearer <AUTH_PASSWORD>` 或合法 Cookie |
| **安全防御** | 仅依赖网络层隔离 | 连续多次错误密码尝试触发短时锁定（防暴力破解） |

### 3.2 敏感数据保护
- API Key 在配置界面显示时默认脱敏展示（如 `sk-...xxxx`）。
- 配置文件落盘在 Docker 挂载数据卷（`/app/data`），与代码仓库分离。

## 4. 网页化配置中心（取代手动修改配置文件）

### 4.1 数据流向
```
[ 网页前端: 点击保存 ]
       │
       ▼ (POST /api/settings)
[ 服务端校验与加密存储 ] ──写入──> data/bbm_providers.json (持久化)
       │
       ▼ (动态生效)
[ 任务调度与翻译引擎加载 ]
```

### 4.2 配置中心覆盖维度
1. **翻译服务商 (Providers)**:
   - 内置主流预设：OpenAI、Gemini、Claude、DeepLX、Qwen、Groq、Ollama、SiliconFlow 等。
   - 自定义 OpenAI 兼容端点：自定义 Base URL、模型名称、Headers。
   - 快速测通（Ping/Test Connection）按钮：测试当前 Key 与端点是否可用。
2. **全局翻译偏好**:
   - 目标语言（默认简体中文、繁体中文、英文等）。
   - 双语排版风格（原文在上 / 译文在上 / 单语输出）。
   - 提示词模板（System Prompt 可选、自定义提示词、术语表上传）。
3. **任务运行时偏好**:
   - 并发限制（默认单任务串行，避免多本并行撞击 API Rate Limit）。
   - 请求重试次数与间隔延时。

## 5. 批量处理与任务队列管理

### 5.1 批处理流程
1. **拖拽上传**：前端支持多文件同时选择（支持 `.epub`, `.pdf`, `.txt`, `.srt` 等）。
2. **参数确认**：上传时可沿用“全局默认配置”，也可针对特定书籍覆盖（如单独修改翻译模型或提示词）。
3. **后台队列**：
   - 任务进入状态队列：`PENDING`（排队中）-> `PROCESSING`（翻译中）-> `COMPLETED`（已完成）/ `FAILED`（失败）。
   - 长耗时任务异步运行，支持查看实时日志、翻译段落进度计数（如 `45/1200 段`）。
   - 支持终止正在进行的任务或断点续翻（复用既有缓存 ledger 机制）。
4. **下载与清理**：
   - 翻译完成的文件提供在线下载，支持多选打包下载为 zip。
   - 提供自动/手动清理上传原文件与中间产物的功能。

## 6. 容器化部署架构（Docker）

### 6.1 单容器标准结构
- 镜像基础：基于精简 Python 镜像（如 `python:3.11-slim`）。
- 服务组合：Uvicorn 驱动的 FastAPI 负责提供 REST API，并兼任静态前端文件（Vue/React 单文件或轻量原生 HTML/JS）的托管。
- 资源占用极低：空闲内存预计低于 80MB。

### 6.2 持久化挂载目录约定
宿主机挂载统一的 `/app/data` 目录：
- `/app/data/config/`：存放 `bbm_providers.json` 与网页端运行时配置。
- `/app/data/uploads/`：暂存上传的原始外语书籍。
- `/app/data/output/`：存放翻译完成的双语书籍产物。
- `/app/data/tasks.db`：轻量 SQLite 数据库，用于存储历史任务状态与配置。

### 6.3 典型运行命令参考
```bash
# 模式 A: 局域网/组网免密模式
docker run -d \
  --name bbm-station \
  -p 8080:8080 \
  -v $(pwd)/bbm_data:/app/data \
  bbm-web:latest

# 模式 B: 公网暴露密码保护模式
docker run -d \
  --name bbm-station \
  -p 8080:8080 \
  -e AUTH_PASSWORD=YourSecurePassword123 \
  -v $(pwd)/bbm_data:/app/data \
  bbm-web:latest
```

## 7. 代码与实现边界（如何做到“尽可能少修改原有代码”）

1. **零改动调用现有业务逻辑**：
   - 将现有 `book_maker/cli.py` 或核心加载器封装为无状态任务执行模块：
   - 方式一（推荐）：将参数组装为 CLI 参数直接在后台异步拉起子进程调用 `python -m book_maker`，stdout 重定向至任务日志文件。优点是绝对不修改原代码一行，原项目的异常隔离与崩溃处理直接继承。
   - 方式二：提取现有模块的类（`EPUBBookLoader`、`PDFBookLoader` 等），以 Python API 形式直接调用。
2. **新增文件独立存放**：
   - 所有 Web 相关代码集中在独立的模块（如 `web_server/`），不修改 `book_maker/` 内部代码。
   - 统一入口通过外部开关或独立容器入口点（`web_server/main.py`）启动。
